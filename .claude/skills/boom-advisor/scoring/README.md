# 股票池五维评分（boom-advisor/scoring）

对 boom-tracker 股票池逐股计算五维评分：护城河、定价、技术面、弹性、确定性。
量化部分完全确定：同一份数据重跑结果逐字节一致；结果随时间变化只反映行情与财务数据本身的变化。
定性部分（护城河/确定性/风险/周期位置）冻结在 `qualitative.py`，人工维护，不随运行漂移。

## 运行

```bash
# 前置：investool 服务已启动（go run main.go webserver -c config.toml）
bash run.sh
# 产出：
#   misc/data/boom_scores/boom_scores_<数据日期>.json  ← 后端接口数据源，同日期重跑覆盖
#   仓库根目录 boom_scores_<数据日期>.md               ← 人读版
```

## 查看报告

- 页面：http://localhost:4869/invest/boom-scores （列表点击进详情，支持全部/持仓/预警筛选）
- 接口：`GET /api/boom/scores` 报告列表（date/generatedAt/total/held/alertCount），
  `GET /api/boom/scores/:date` 完整报告 JSON（handler 在 api/boom_scores.go，
  目录可用配置 boom_tracker.scores_dir 覆盖）

## 五维标准（全部阈值）

### 1. 护城河（0~10，定性，存于 qualitative.py）
五维度各 0~2：市场地位（全球/国内第一 2，前三 1）、技术专利壁垒、成本规模优势、
客户粘性与转换成本、牌照/资源/配额独占。≥8 宽 / 5~7 中 / 3~4 弱 / ≤2 无。

### 2. 定价（按行业选 1~3 维度，映射在 qualitative.py 的 SECTOR_PRICING / STOCK_PRICING_OVERRIDE）

成长评分（三项求和；≥4 显著低估 / 2~3 合理偏低 / 0~1 合理 / -1~-2 偏贵 / ≤-3 透支）：
| 项 | 规则 |
|---|---|
| PEG = PE÷预测增速 | <0.8:+2 <1.2:+1 <2:0 <3:-1 否则-2；增速≤0 直接 -2 |
| 三年预期PE = PE÷(1+g)(1+0.6g)(1+0.4g)，g=min(预测增速,100%) | <15:+2 <25:+1 <35:0 否则-1 |
| 行业增速（SECTOR_GROWTH 代理值） | >30%:+1 10~30%:0 <10%:-1 |

红利评分（两项求和；≥3 低估 / 1~2 合理偏低 / 0 合理 / <0 偏贵）：
| 项 | 规则 |
|---|---|
| PE | <10:+2 <15:+1 <25:0 否则-1 |
| 4年PE分位 | <30%:+2 <50%:+1 <70%:0 否则-1；缺失记 0 |

周期位置（定性四段，存于 qualitative.py）：底部区 / 左侧回升 / 右侧上行（右侧后段）/ 高位过热。
周期股不用 PE 分位加减分（低 PE 常见于周期顶）。

### 3. 技术面（日线 0~5 + 周线 0~5）
日线：收盘>MA20 +1；>MA60 +1；MA20>MA60 +1；距60日新高<5% +1；MACD金叉 +1。
周线：收盘>20周线 +2；>30周线 +1；周MACD金叉 +1；红柱扩张 +1。
合计 ≥8 强趋势 / 5~7 健康 / 3~4 走弱 / ≤2 空头排列。
预警标注：跌破MA60（对应龙头减半纪律）、跌破20周线（对应清仓纪律）、RSI14>80 过热、<30 超卖。

### 4. 未来弹性（高/中/低）
市值 <200亿:+2 200~800亿:+1 >2000亿:-1；年化波动率(120日) >60%:+2 >40%:+1 <30%:-1；
预测增速>60%:+1；role=elastic:+1。总分 ≥4 高 / 2~3 中 / ≤1 低。

### 5'. 操作策略（规则引擎，compute.py 的 strategy()）
辅助量：低估 = 成长分≥2 或红利分≥2；偏贵 = 成长分≤-1 或红利分≤-1；
优质 = 护城河≥7 且确定性 A/B；涨幅过大 = 20日涨幅≥20% 或 RSI14≥80；
破20日线未收回 = 连续3日收盘低于当日MA20；深度破位 = 同时低于60日线与20周线。

持仓（优先级从上到下）：
1. 周期高位过热 → 卖出
2. 偏贵 且（涨幅过大 或 破20日线未收回）→ 卖出
3. 偏贵 → 反弹减仓一半
4. 涨幅过大 且非低估 → 减仓一半
5. 周期右侧后段 ＋ 破位 → 减仓一半
6. 深度破位 且非（优质＋低估）→ 卖出
7. 优质＋低估＋破位 → 左侧加仓3成（挂单价=现价-4%与20周线取高者，跌破20周线暂停）
8. 站上20日线 → 持有，回踩20日线可加仓；否则 → 持有，卖出线=连续3日收不回20日线

未持仓：
1. 偏贵/周期高位 → 回避
2. 涨幅过大 → 观望等回调
3. 优质＋低估＋站上20日线 → 右侧买入3成（跌回20日线止损）
4. 优质＋低估（20日线下方）→ 左侧买入3成（同上挂单价规则）
5. 仅低估 → 观望，站稳20日线再右侧介入；其余 → 观望

港股缺估值数据时只走技术面规则并标注。页面不再展示技术面预警，破位信息体现在策略文本里。

### 5. 确定性（A~D，定性，存于 qualitative.py）
五个风险维度做减法：业绩可见度、竞争格局、政策地缘、技术路线替代、财务治理。
A 无重大瑕疵 / B 1~2个可跟踪风险 / C 有可能改变逻辑的重大风险 / D 依赖单一假设或已恶化。
每股附一句"最大挑战"。

## 文件

- `collect.py` — 采集：本地服务(股票池+A股基本面) + 腾讯K线(日/周，A股港股通用) + 东财emfront(PE分位)。中间产物 /tmp/scores_raw.json
- `qualitative.py` — 定性表 + 行业定价维度映射 + 行业增速代理 + 港股市值近似。**这是唯一需要人工维护的文件**
- `compute.py` — 打分与报告生成，纯函数无网络
- `run.sh` — 串起来

## 已知坑

- 东财 push2his K线接口对脚本批量请求限流（curl/urllib 均被拒连），故 K线用腾讯 `web.ifzq.gtimg.cn/appstock/app/fqkline/get`
- 池内港股代码存储格式为"后两位.前三位"（988.09 = 09988）
- 港股无 PE/预测增速（batch-prices 只返回价格），定价维度输出"数据缺失"
- emfront PE 分位接口偶发失败，缺失时红利分的分位项记 0 并标注
- 新增标的后 compute.py 会打印"定性表缺失"提醒，先补 qualitative.py 再采信结果
